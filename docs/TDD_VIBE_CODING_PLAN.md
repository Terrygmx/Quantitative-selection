# TDD 开发计划：A 股多策略 Agent 量化平台

## 0. 开发原则

按小步闭环开发：先写失败测试（Red），只写使其通过的最小实现（Green），最后重构（Refactor）。每个 Vibe Coding 会话只处理一个可验证切片；禁止“先生成整个平台，再补测试”。

完成定义（DoD）：测试通过、类型/静态检查通过、公开接口有文档、运行清单可生成、没有未解释的数据泄漏或规则绕过。

## 1. 里程碑与依赖

| 阶段 | 交付物 | 先决条件 | 验收门槛 |
|---|---|---|---|
| M0 基线 | 测试骨架、遗留夹具、CLI 帮助修复 | 无 | 现有脚本编译、`--help` 可运行、夹具入库 |
| M1 领域核心 | 值对象、时钟、运行清单 | M0 | 领域单测通过，无 IO 依赖 |
| M2 A 股规则 | 日历、T+1、整手、价格带、交易状态 | M1 | 规则回归矩阵全绿 |
| M3 数据门户 | 原始/标准数据、PIT 查询、质量事件 | M1 | 未来数据查询被拒绝 |
| M4 回测器 | 事件时钟、订单、成交、账本、指标 | M2+M3 | 可复现日频基准回测 |
| M5 插件与首策略 | 注册表、尾盘动量迁移、报告 | M3+M4 | 与遗留样本差异可解释 |
| M6 多策略组合 | 信号合成、风险预算、组合约束 | M5 | 冲突信号有唯一审计结果 |
| M7 模拟盘和 Agent | 调度、只读 Agent Gateway、审阅报告 | M6 | Agent 无法越权，dry-run 成功 |
| M8 质量闸门 | CI、覆盖率、性能基准、运行手册 | M0-M7 | PR 检查和演练全部通过 |

## 2. 测试先行的实现切片

### Slice A：项目骨架与遗留保护（M0）

1. 新增 `pytest`、格式化、类型检查和最小 CI 配置。
2. 写 `test_legacy_cli_help.py`，复现 `--help` 失败；修复帮助文案中的百分号转义。
3. 从 `cache/` 与 `results/` 提取脱敏、小型固定夹具；写 Markdown 解析、股票池解析和报告快照测试。
4. 建 `tests/fixtures/README.md`，说明数据来源、许可和生成命令。

验收：只运行测试而不访问网络；遗留功能无意外改动。

### Slice B：不可变领域模型（M1）

先写：`Instrument` 拒绝缺板块；`Signal` 拒绝越界权重；`Order` 拒绝非整手；`RunManifest` 固定哈希。

再写最小 `dataclass`/Pydantic 实现和序列化；最后重构通用校验。禁止接数据库或行情接口。

### Slice C：A 股规则引擎（M2）

先写表驱动测试：

| 用例 | 期望 |
|---|---|
| 主板普通股 | 适用对应日期的涨跌幅配置 |
| 科创板/创业板 | 使用 20% 配置，不继承主板默认值 |
| 新股前五日 | 规则返回“无固定涨跌幅”，风控采用单独准入策略 |
| T 日买入再卖 | 卖单被拒，原因 `T1_UNSETTLED` |
| 100 股整手和剩余零股 | 按规则允许/拒绝 |
| 涨停、跌停、停牌 | 无法按不合法价格成交 |

实现日期生效的 `TradingRulesPlugin`，再补性质测试：对任意合法订单，成交后现金和持仓守恒且持仓不为负。

### Slice D：Point-in-Time 数据门户（M3）

先写：14:30 上下文只能返回不晚于 14:30 的 K 线；修订数据在其 `available_at` 前不可见；缺关键数据生成 `block` 事件。

实现内存数据集，再增加 Parquet/DuckDB 适配器。每加一个供应商，先写同一份 `MarketDataPort` 契约测试。

### Slice E：最小回测闭环（M4）

先写一只股票、三天数据的金样本：信号在 T 日产生，T+1 才可卖；费用、滑点、现金和权益符合手算结果。

实现事件时钟、订单状态机、成交器和账本。再写“不得用当前收盘生成并以当前收盘成交”的失败测试。最后加入指标与报告。

### Slice F：策略注册与尾盘动量迁移（M5）

先写插件发现失败、参数非法、窗口不足、未来分钟不可见、固定夹具信号一致等测试。把当前策略拆成：数据适配器、纯因子、`tail_momentum_overnight` 插件和报告模板。只在测试证明等价后删除重复代码。

### Slice G：多策略组合与风险（M6）

先写相反信号、超单票上限、超行业上限、流动性不足、回撤熔断和黑名单测试。实现“信号标准化 → 净目标 → 风险审批”的单向流程。风险结果必须带原因码。

### Slice H：Agent Gateway 与模拟盘（M7）

先写权限测试：研究 Agent 无法提交订单、改生产配置或跳过 `block` 数据事件；结构化输出不合格时必须拒绝。实现只读工具和草稿工件，再接模拟盘调度。所有 Agent 工件绑定 RunManifest。

## 3. Vibe Coding 会话模板

每个会话使用以下提示，不超过一个切片：

```text
目标：完成 <切片名称> 的最小纵向能力。
先阅读 docs/PRODUCT_REQUIREMENTS.md 与 docs/DETAILED_DESIGN.md 的相关章节。
先新增/修改失败测试；不得改测试来迎合错误实现。
仅实现使这些测试通过的最小代码。保持 domain 无 IO。
运行指定测试、全量测试、类型检查与格式化；报告命令和结果。
不要访问网络，不要修改策略参数，不要删除遗留代码或数据。
提交前列出改动、未覆盖风险与下一最小切片。
```

## 4. 每次合并请求检查清单

- [ ] 有失败后转绿的测试证据。
- [ ] 新策略/数据适配器通过契约测试。
- [ ] 无未来数据、无 T+0 卖出、无无效价格成交。
- [ ] `RunManifest` 包含配置、数据和代码版本。
- [ ] Agent 变更有权限回归测试。
- [ ] 产物不含密钥、账户或不可公开原始数据。
- [ ] 文档与示例命令同步更新。

## 5. 建议开发顺序

优先完成 M0-M5，才能形成“尾盘动量策略在 A 股约束下可复现回测”的最小可信产品。M6 用于真正的多策略，M7 才引入 Agent 和模拟盘。实盘接口仅在至少一段模拟盘稳定运行、审计和人工审批流程验收后另立需求评审。

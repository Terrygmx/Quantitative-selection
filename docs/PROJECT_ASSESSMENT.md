# 项目现状评估

评估日期：2026-10-24。范围为当前工作区，不改动任何现有策略或产物。

## 结论

现有项目是一个可验证思路的尾盘动量扫描器，不是可扩展的量化平台。它保留为首个策略的参考实现最合适；不应在原脚本上继续叠加回测、组合、交易和 Agent 功能。

## 已有资产

| 项目 | 现状 | 可迁移价值 |
|---|---|---|
| 策略 | `src/tail_momentum_selector.py`，1,358 行 | 尾盘动量因子、评分和信号样本 |
| 数据接入 | `westock`/旧版 CLI 适配 | 可封装为首个 `MarketDataPort` 适配器 |
| 输出 | 文本报告、JSON 信号、自包含 HTML | 可迁移为报告渲染器和审计样本 |
| 防未来函数 | 用分时快照覆盖当日日线收盘 | 应提升为平台级 Point-in-Time 契约 |
| 领域规则 | ST 排除、行业相对强弱、弱市阈值 | 可转为可配置的准入与风控规则 |

## 阻塞与风险

1. 单文件把 CLI、解析、行情、因子、选股、报告和复盘耦合在一起；新增策略会复制代码。
2. 没有测试目录、测试数据或 CI，不能证明因子、反未来函数和复盘结果正确。
3. 评分、阈值、持仓上限写在流程中，不能版本化、比较或复现策略实验。
4. `--help` 当前报错：帮助文本内的百分号被 `argparse` 当作格式占位符。代码能编译，但 CLI 的基础自检失败。
5. 当前信号 JSON 仅保存候选结果和很少的环境信息，缺少数据版本、策略版本、因子快照、成本模型和订单模拟记录。
6. 工作区已有未提交的 CLI 兼容和股票池解析改动；本轮设计不覆盖这些用户改动。

## 迁移原则

- 冻结现有脚本为 `legacy` 基线，先用它的缓存与信号做回归样本。
- 新平台按“端口 + 领域核心 + 插件”的边界新建，不直接 import 旧脚本内部函数。
- 先实现研究、回测和模拟盘；真实下单是后续独立里程碑，默认关闭。
- 所有策略、数据与结果都需携带不可变版本和运行 ID。

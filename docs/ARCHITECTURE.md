## 3. 防未来函数（Iron rule）

- 决策时刻 `SNAPSHOT`（默认 `1430`）。只使用该时刻**及之前**的分时价格、成交量、成交额与历史日线。
- 日线 `kline` 的「当日」一行是 15:00 收盘值 → 程序用 `SNAPSHOT` 时刻的分时价格**覆盖**它，再做均线/动量计算。
- 收盘后运行 = 用当日已发生数据在快照时刻做**回放验证**，仍不引入未来数据。
- 修改行情/因子逻辑时，务必复核这一点，避免引入 look-ahead。

## 4. 评分模型（100 分）

| 维度 | 分值 | 要点 |
|---|---|---|
| 趋势 | 20 | 均线多头、价格站上短中期均线、趋势改善 |
| 下午动量 | 25 | 14:00 后上涨、下午相对上午加速、突破日内高点 |
| 成交量/成交额 | 20 | 量比放大、价涨量增（方向一致） |
| 相对强弱 | 15 | vs 沪深300 / 中证1000 / 申万行业（各 5 分） |
| 市场环境 | 10 | 指数趋势 + 市场广度（与 Bull/Neutral/Bear 标签对齐） |
| 风险控制 | 10 | 流动性、是否过热、是否接近涨停 |

**买入硬条件**（全部满足）：总分 ≥ 70（Bear 环境 ≥ 80）且 下午动量 ≥ 12 且 价涨 + 量比 ≥ 1
且 强于指数 且 流动性 ≥ 1 亿 且 未接近涨停过热。

## 6. 开发约定

1. **缓存与产物分离**：一切中间缓存写 `cache/`（已忽略），一切交付成果写 `results/`（已跟踪）。
2. **结果文件带日期后缀**：`<type>_YYYY-MM-DD.<ext>`。
3. **跨平台文本 I/O**：子进程输出必须用字节模式读取后显式 `decode("utf-8", errors="replace")`，
   避免 Windows 默认 GBK 解码崩溃；文件读写显式指定 `encoding="utf-8"`。
4. **零第三方 Python 依赖**：新增依赖前先在 `requirements.txt` 声明并说明理由。
5. **诚实披露**：概率不得伪装成统计值；数据不足时明确说明，不强行产出信号。

# A 股多策略 Agent 量化平台：需求说明

## 1. 产品定位

建设一个面向 A 股现货的研究、回测和模拟交易平台。策略以插件形式接入；Agent 负责研究辅助、质量检查、解释和开发协作，确定性的策略引擎和风险引擎保留最终决策权。

首期不是荐股产品，也不接券商真实下单。任何候选、回测或 Agent 结论均是研究产物，不构成投资建议。

## 2. 目标与非目标

| 目标 | 首期非目标 |
|---|---|
| 多策略独立开发、发现、启停与版本回滚 | 实盘自动下单和资金划转 |
| 严格 Point-in-Time 回测与可复现实验 | 覆盖期权、期货、港股和 B 股 |
| A 股交易约束、成本、停牌和涨跌停模拟 | 预测收益或保证收益 |
| 多策略信号合成、组合风险控制、模拟盘 | 由 LLM 直接决定仓位或绕过风控 |
| Agent 生成可审计的研究辅助产物 | 未经批准的在线数据抓取或策略发布 |

## 3. 范围与市场规则

### 3.1 首期市场范围

- 标的：上交所和深交所 A 股普通股，含主板、科创板和创业板。
- 默认排除：ST/*ST、退市整理、停牌、上市未满配置天数、无涨跌幅限制阶段、流动性不足证券。
- 北交所、ETF、可转债、融资融券、期权和实盘券商接口留作后续插件，不与首期规则混用。
- 日内策略可研究，但现货账户的卖出可用数量必须遵守 T+1；回测和模拟盘不得用当日新买仓位平仓。

### 3.2 必须配置化的交易约束

`TradingRulesPlugin` 按交易所、板块、证券状态和交易日期给出：交易日历、连续竞价时段、最小价格变动、最小申报单位、可交易性、涨跌幅和下单价格带。

主板、科创板和创业板并不共享同一涨跌幅；科创板、创业板通常为 20%，新股前五个交易日还可能不设涨跌幅。因此策略风控不得以固定 10% 处理全市场。规则须有生效日期，避免规则变化污染历史回测。[上交所 2026 年交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml) [深交所创业板交易特别规定](https://www.szse.cn/lawrules/rule/repeal/rules/P020231230545310237980.pdf)

## 4. 用户、场景和核心流程

| 用户 | 场景 | 成功标准 |
|---|---|---|
| 研究员 | 新建、参数化并比较策略 | 相同输入与版本能复现同一结果 |
| 策略开发者 | 新增插件与测试夹具 | 不改平台核心即可被注册和运行 |
| 风控/审阅者 | 审核信号、订单和 Agent 解释 | 能追溯规则、数据、版本和否决原因 |
| 操作员 | 日终或盘中运行模拟盘 | 异常数据、越限、停牌自动拒绝并留痕 |

核心流程：导入原始数据 → 数据质量校验与标准化 → 策略产生信号 → 信号合成 → 组合与交易规则校验 → 回测/模拟成交 → 指标、归因与审计报告。

## 5. 功能需求

### FR-1 策略插件

1. 支持 `daily`、`intraday`、`event` 三类策略及参数 Schema。
2. 每个插件声明所需数据频率、预热窗口、适用市场、信号含义、换手上限和风险暴露。
3. 平台发现插件、校验接口、记录版本；插件失败隔离，不影响其他策略。
4. 首个迁移策略是“尾盘动量隔夜”；随后加入趋势、均值回归和低波动/行业轮动作为独立插件。

### FR-2 数据与时间一致性

1. 以原始、标准化、特征三层存储数据，并保存来源、拉取时间、修订版本与校验结果。
2. 任一回测仅可读取 `as_of` 时刻可获得的数据；复权、成分股、停复牌和公告数据均需 Point-in-Time 版本。
3. 数据缺口、重复 K 线、异常价格、时间戳越界必须产生质量事件；默认阻止受影响策略发交易信号。

### FR-3 回测与模拟盘

1. 支持日频和分钟频回测、滚动窗口、样本内/样本外划分及基准比较。
2. 模拟成交包括佣金、印花税、滑点、最小单位、涨跌停、停牌、T+1、现金和持仓限制。
3. 输出净值、年化收益、最大回撤、夏普、胜率、换手、容量和逐笔成交记录。
4. 模拟盘复用同一策略、规则和订单通道；不可复用“回测特权”。

### FR-4 多策略组合与风险

1. 统一将策略输出转成标准 `Signal`，按目标权重、置信度和有效期合成。
2. 组合层处理同标的冲突、行业集中度、单票上限、总仓位、流动性参与率、回撤熔断和黑名单。
3. 风控拒绝必须返回机器可读原因和人类可读说明。

### FR-5 Agent 协作

1. 研究 Agent 可提出假设、解释信号、起草实验配置和报告，但只能写入草稿区。
2. 数据质量 Agent 检查缺失、时间泄漏和供应商偏差；风险 Agent 解释拒绝；审阅 Agent 检查实验完整性。
3. Agent 的提示词、工具调用、输入摘要、模型标识、输出和人工批准均与运行 ID 关联。
4. Agent 不拥有下单、改生产规则、发布策略或删除数据权限。

### FR-6 可用性与运维

1. CLI 先行：`strategy list`、`backtest run`、`paper run`、`report show`、`agent review`。
2. 运行状态可查询；失败可重试；产物按运行 ID 归档。
3. 提供 HTML/Markdown 报告和结构化 JSON/Parquet 导出。

## 6. 非功能需求与验收门槛

| 类别 | 门槛 |
|---|---|
| 正确性 | 核心领域和策略插件单元测试覆盖率不低于 90%；反未来函数、T+1、涨跌停为强制回归用例 |
| 可复现 | 固定数据快照、配置和随机种子后，指标和订单逐笔一致 |
| 可靠性 | 数据源单点失败可降级，缺关键数据时 fail closed，不产生可交易信号 |
| 安全 | 密钥仅在运行环境；审计日志只追加；默认无实盘执行权限 |
| 性能 | 以 3,000 只股票、5 年日线作为首期日频回测性能基准；分钟频采用分区和批处理 |
| 可维护 | 新策略仅新增插件、配置和测试，不修改领域核心；所有接口有契约测试 |

## 7. 关键验收场景

1. 给定历史分钟数据，尾盘动量策略在 14:30 运行时绝不能看到 14:31 之后数据。
2. 当日买入 100 股后，卖出订单在同一交易日必须被 T+1 规则拒绝。
3. 股票涨停、停牌、超出价格带或不满足最小申报单位时，订单必须被拒绝或按模型未成交。
4. 两个策略对同一股票给出相反目标时，组合层输出唯一净目标及决策原因。
5. 任一 Agent 给出高置信度文本也不得绕过确定性风险规则。
